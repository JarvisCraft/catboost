# AVX-512 в CPU-эвалюаторе CatBoost

Что сделано, где это лежит, как это проверять и как замерять.

Отправная точка — статья `paper.pdf`, её конспект в
[`paper-summary.md`](paper-summary.md).

## Что добавлено

### 1. Ядра AVX-512 — `catboost/libs/model/cpu/avx512_kernels.h`

Чистые интринсики, без зависимостей от типов CatBoost, поэтому их можно собрать
отдельно и проверить (см. «Проверка корректности»). Три ядра:

* **`CalcIndexesAvx512`** — подсчёт индексов листьев одного oblivious дерева.
  64 документа на регистр вместо 16 у SSE. Внешний цикл — по глубине, внутренний
  — по регистрам, так что `vpbroadcastb` границы разделения делается один раз на
  уровень для всех восьми аккумуляторов (в AVX-512 32 регистра, места хватает).
  Сравнение — `vpcmpub` в маску, установка бита — `_mm512_maskz_set1_epi8`;
   SSE-версии для этого нужны `cmpeq(max(a,b),a)` и сдвигаемая маска.
* **`CalculateLeafValuesAvx512` / `CalculateLeafValues4Avx512`** — загрузка и
  суммирование значений листьев через `vgatherdpd`, по 8 `double` за раз;
  вариант на четыре дерева платит за проход по буферу результатов один раз
  вместо четырёх. В отличие от SSE-версии, выравнивание буфера не требуется.
* **`BinarizeFloatsAvx512Impl`** — квантилизация одного числового признака,
  64 документа за итерацию. Читает документы прямо из памяти (см. п. 3).

**Хвосты обрабатываются теми же векторами под маской**, а не скалярным
эпилогом — это прямая рекомендация статьи (раздел 9.4): недозаполненный вектор
дешевле, чем несколько скалярных итераций, а маски AVX-512 делают это бесплатно.
Маскированные загрузки не трогают память за концом блока, поэтому выходов за
границы буфера не возникает.

### 2. Эвалюатор — `catboost/libs/model/cpu/evaluator_impl_avx512.cpp`

Собирается отдельной единицей трансляции с `-mavx512f -mavx512cd -mavx512bw
-mavx512dq -mavx512vl` (группа `.avx512` в сгенерированных `CMakeLists`), по
образцу `library/cpp/dot_product`. Структура повторяет `CalcTreesBlockedImpl` из
`evaluator_impl.cpp`: четвёрка деревьев за проход, затем остаток по одному;
деревья глубже 8 и режим «только индексы листьев» уходят в общий
`CalcIndexesBasic`.

Диспетчеризация — в `GetCalcTreesFunction`: если `HaveAvx512Evaluator()`, сначала
спрашивается `GetCalcTreesFunctionAvx512`, и он возвращает пустую функцию для
случаев, которых не покрывает (неoblivious деревья, один документ). Сама проверка
CPU живёт в `quantization.cpp` — единице трансляции **без** AVX-512-флагов, иначе
компилятор мог бы поставить AVX-512 инструкцию в код, который выполняется до
проверки.

Общие для baseline и AVX-512 шаблоны вынесены в
`catboost/libs/model/cpu/evaluator_common.h` (`CalcIndexesBasic`,
`CalculateLeafValues`, `CalculateLeafValuesMulti`,
`FunctorTemplateParamsSubstitutor`).

### 3. Бинаризация транспонированного входа

`BinarizeFloats` в `quantization.h` читает признаки по одному документу через
аксессор-лямбду. Для транспонированного входа документы одного признака лежат
подряд, и теперь аксессор об этом сообщает: `TTransposedFloatFeatureAccessor` в
`formula_evaluator.cpp` предоставляет `GetContiguousData(position, start)`, а
трейт `TIsContiguousFloatAccessor` в `quantization.h` это обнаруживает. Если
аксессор непрерывный и CPU умеет AVX-512, признак уходит в `BinarizeFloatsAvx512`
с векторными загрузками. Для нетранспонированного входа (`CalcFlat`,
`CalcFlatSingle`, пул-адаптер) ничего не меняется.

Тонкость упаковки: `vpackssdw`/`vpacksswb` перемешивают операнды внутри каждой
128-битной полосы, поэтому результат сравнений выходит переставленным группами по
4 байта. Референсная реализация из статьи обходит это, читая документы в
переставленном порядке; здесь загрузки остаются последовательными, а порядок
восстанавливается одним `vpermd` — так работает загрузка прямо из памяти.

### 4. Размер блока для транспонированного пути

По статье это даёт больше, чем ширина регистров: для транспонированного входа
время монотонно падает с ростом блока, для нетранспонированного оптимум — 128.
`FORMULA_EVALUATION_BLOCK_SIZE` (128) остался константой, но
`BinarizeFeatures`/`ProcessDocsInBlocks`/`CalcGeneric` теперь принимают размер
блока параметром, и `CalcFlatTransposed` выбирает его через
`GetTransposedEvaluationBlockSize`: **512**, если активен AVX-512 эвалюатор и
модель oblivious, иначе 128. Ограничение не косметическое: baseline
`CalcTreesBlocked` умеет только 8 SSE-блоков по 16 документов.

Переменная окружения `CATBOOST_TRANSPOSED_BLOCK_SIZE` понижает этот размер — для
sweep'а, как в разделе 9.1 статьи. Поднять выше того, что умеет активный
эвалюатор, она не может.

Побочный эффект: буфер квантилей — это `размер блока × число бинарных бакетов`,
то есть при блоке 512 он вчетверо больше. Для модели с 2000 признаков это 1 МБ
вместо 256 КБ на вызов `CalcFlatTransposed`. Аллокация одна на вызов, не на блок.

### 5. `library/cpp/dot_product`

Добавлен `dot_product_avx512.{h,cpp}` с 512-битными версиями для `float`,
`double`, `i32`, `ui8`, `float×i8` и `TriWayDotProduct`. Int8-пути оставлены
существующим VNNI/AVX2 реализациям — VNNI это уже AVX-512 и для i8 оптимальнее.
Диспетчеризация — в `dot_product.cpp`, отключается переменной
`Y_NO_AVX512_IN_DOT_PRODUCT`. Для длин меньше 32 элементов вызывается AVX2
версия.

## Переключатели

| Переменная | Действие |
|---|---|
| `CATBOOST_NO_AVX512=1` | Полностью выключает AVX-512 эвалюатор и AVX-512 бинаризацию; размер блока возвращается к 128 |
| `CATBOOST_TRANSPOSED_BLOCK_SIZE=N` | Понижает размер блока транспонированного пути до N |
| `Y_NO_AVX512_IN_DOT_PRODUCT=1` | Выключает AVX-512 в `library/cpp/dot_product` |

## Проверка корректности

### Юнит-тесты в дереве

`catboost/libs/model/ut/avx512_evaluator_ut.cpp` (цель `model_ut`, набор
`TAvx512Evaluator`) сверяет батчевое применение с поштучным на размерах батча
1…1000, включая границы 64/128/512 и соседние с ними. На машине с AVX-512
батчевый путь — это AVX-512 эвалюатор, а поштучный — скалярный код, то есть это
ровно сверка новой реализации с baseline. Покрыты неглубокие деревья, глубина 8,
глубина 10 (fallback), многоклассовая модель и вычисление индексов листьев.

**Статус:** 40 тестов `model_ut` проходят на Ryzen 9 5950X (Zen 3, без AVX-512) —
то есть baseline-поведение не сломано. На AVX-512 хосте их надо прогнать заново,
и это главная непроверенная здесь вещь.

### Автономная проверка ядер

`avx512-results/kernel_check/` собирает ядра отдельной программой и сверяет их со
скалярной транскрипцией того, что считает baseline, на случайных данных и на всех
размерах, задевающих маскированные хвосты. Два режима:

* `native` — настоящие интринсики, нужен AVX-512 хост;
* `simde` — те же исходники через [SIMDe](https://github.com/simd-everywhere/simde),
  работает где угодно и проверяет **алгоритм** (маски, порядок упаковки и
  перестановки, смещения gather), а не железо.

```sh
./avx512-results/kernel_check/build_and_run.sh          # native, если CPU умеет, иначе simde
./avx512-results/kernel_check/build_and_run.sh simde
```

SIMDe реализует маскированные load/store как полный доступ к памяти с последующим
blend'ом; железо в замаскированные полосы не ходит, и ядра на это опираются,
поэтому в `avx512_simde_compat.h` они заменены на точную поэлементную эмуляцию —
иначе проверка под ASan сообщала бы о выходах за границы, которых на AVX-512 не
бывает.

**Статус:** оба набора (`check_kernels`, `check_dot_product`) проходят в режиме
`simde`, в том числе под `-fsanitize=address`.

## Замеры

`avx512-results/benchmark/` — бенчмарк поверх C API, то есть меряет ровно ту
библиотеку, которую собирает `nix build`.

```sh
nix build                                     # даёт ./result/lib/libcatboostmodel.so

# модель нужного размера (или возьмите свою .cbm)
nix develop .#benchmark -c python3 avx512-results/benchmark/make_model.py --output /tmp/bench.cbm

# два прогона: с AVX-512 и с CATBOOST_NO_AVX512=1
./avx512-results/benchmark/build_and_run.sh --model /tmp/bench.cbm --docs 1024 --repetitions 200
```

Бенчмарк печатает контрольную сумму предсказаний; она должна совпасть между
прогонами с AVX-512 и без него, и между транспонированным и нетранспонированным
входом (последнее он проверяет сам и падает с ненулевым кодом при расхождении).

Для устойчивых чисел стоит прибивать процесс к ядру (`taskset -c N`) — эвалюатор
однопоточный, как и в статье.

Результаты — в [`results.md`](results.md).
